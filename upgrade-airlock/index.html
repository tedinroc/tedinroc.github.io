How it works

A proxy upgrade runs only after a block cooldown and an on-chain clearance. A Chainlink CRE workflow runs the new implementation against the proxy's real state, has a funded outside account call every new function, and compares supply, ownership and balances before and after. If the attack works, the upgrade gets a signed veto. A bytecode rule also catches code that behaves well in simulation but mints tokens on a real block.

Of the first ten proposals on the Sepolia testnet, the one honest upgrade was cleared and executed, and all nine test attacks were vetoed. I entered solo. Solidity and Foundry for the contracts, TypeScript for the workflow.
