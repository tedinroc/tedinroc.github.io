04 / How I work

The demo is the start.
The details matter.

I design the systems and use Claude Code and Codex to write most of the code. I review, test and ship the results, documenting what was measured and what remains untested.

  1. 01

    Design the boundaries.

    Make the system’s responsibilities clear: what the model can decide, what code must validate and where a person stays in control.

  2. 02

    Test the failure path.

    A convincing happy path is a start. The more interesting question is what happens when a tool, a server or a proposed upgrade goes wrong.

  3. 03

    Leave the evidence open.

    Publish demos, source and reproducible checks. Keep prototype results distinct from production claims.
